# AI辅助业务域现状调研全流程

## 核心逻辑

**AI 做信息的「初加工、结构化、检索、草稿输出」；你把时间留给访谈、验证、判断、对齐、建立信任。**

AI 不能替代访谈和业务校验，AI 最大价值是减少低价值信息整理时间，把你从读一堆零散文档里解放出来。

**人机分工铁则**：
- 🚫 **AI 判断不了、必须你自己来**：说话人可信度、业务隐性博弈（部门间利益冲突）、组织关系与政治约束（谁有决策权）、言外之意、历史敏感点
- ✅ **放心交给AI**：材料结构化整理、代码/文档信息提取、状态机/流程图/规则表生成、冲突点自动检测、访谈录音纪要提炼、报告草稿输出、待确认清单按角色分类

## 核心原则

1. **零脑补规则**：所有AI输出的正文内容必须有可追溯来源（代码行号/文档章节/数据库字段/工单号），不确定的内容一律列入待确认清单，绝不允许虚构逻辑
2. **现状阶段不做价值判断**：只客观陈述"代码/文档里写了什么、没写什么、哪里矛盾"，不评价设计好坏，不做"应该是XX"的判断
3. **内容不全允许留白**：哪怕某个模块只有1行有效内容也只写1行，剩下的标记为🚫缺口，禁止为了内容完整填充不确定信息
4. **所有异常显式标记**：🚫缺口（找不到/链路断/分支不全）和⚠️冲突（多来源不一致）必须和正文严格区隔
5. **溯源留痕**：所有规则、逻辑、问题必须关联对应代码位置/工单/PRD/负责人，避免成为死文档
6. **边界清晰**：单领域报告严格无重叠框架，涉及其他域只写交互点+文档链接，不展开跨域内部细节

## 前置准备（0-1天）

### 你需要做的

1. **确定首批梳理领域**：建议第一个选边界清晰、历史债少的领域跑通流程，再梳理复杂核心域
2. **按优先级收集原始材料**：

| 材料类型 | 优先级 | 说明 |
|----------|--------|------|
| 领域相关代码+git提交记录 | ⭐⭐⭐⭐⭐ | 最接近真实逻辑的信息源 |
| 数据库表结构+字段注释 | ⭐⭐⭐⭐⭐ | 数据模型的核心依据 |
| 近1-2年JIRA/工单/故障记录 | ⭐⭐⭐⭐ | 提取隐性逻辑、特殊分支、历史问题 |
| 历史PRD/架构文档/测试用例 | ⭐⭐⭐ | 业务规则补充来源，注意标记和代码不一致的地方 |
| 压测报告/监控数据/性能指标 | ⭐⭐ | 非功能现状依据 |

3. **提前对齐领域边界**，明确该域和其他域的大致权责划分

### AI产出
- 材料完整性校验报告，列出缺失的核心材料并提示补充

### 代码走查技巧（给AI的指令要点）

当提供代码给AI分析时，要求AI：
- 从入口（HTTP路由/timer/MQ consumer）出发画出完整调用链路
- 找到状态常量定义，画出状态机骨架
- 逐条提取if/else分支中的业务规则（阈值、校验、拦截条件），每条标注代码文件名+行号
- 专门检查被注释的代码、TODO/FIXME/"暂时"注释、灰度开关控制的路径
- 金额阈值一律以"分"为单位精确计算，同时折合人民币，避免单位错误（2000万分≠2000万元）
- 搜索可疑模式：for循环内的return、错误码复用、注释与代码不一致、空分支/default分支
- **注意"没有"比"有"更重要**：后端没有做的校验（如敏感词只前端校验）、没有最低金额检查——这些"没有"本身就是关键发现
- 不要假设对称路径行为一致（如蓝字发票上传UFile被注释但红字发票活跃——代码不一致本身就是发现）

## 步骤1：领域现状初稿生成（AI自动执行，0.5天）

### AI执行

使用固定Prompt生成初稿（见下方），严格按照调研报告框架输出（框架由 `business-status-report` skill 定义）。

**初稿生成固定Prompt**：
```
【最高优先级强制铁则，违反则输出直接作废】
1. 仅输出可证内容：正文所有内容必须有明确来源，可对应到「具体代码行/文档具体章节/数据库具体字段/工单号」，来源必须精确可查，不允许模糊标记。
2. 零推断零补全：凡没有明确证据的逻辑、场景、规则，一律不补全、不推测、不基于行业经验/常识脑补，哪怕逻辑看起来明显不完整也不自行填充。
3. 现状阶段不做任何价值判断/合理性判断：只客观陈述「代码/文档里写了什么、没写什么、哪里矛盾」，不评价设计好坏、不做"应该是XX"的判断，所有诊断留到后续阶段。
4. 内容不全允许留白：哪怕某一个模块只有1行有效内容，也只写这1行，剩下的全部标记为异常，禁止为了内容完整填充任何不确定信息。
5. 所有异常情况必须显式标记，和正文内容严格区隔，统一分为两类：
   🚫 缺口：符合以下任意一种：
   - 文档未提及、代码中未找到对应实现的逻辑/场景/字段
   - 逻辑链路断裂，缺少中间实现节点
   - 分支逻辑不完整，只有正向流程无异常分支处理
   ⚠️ 冲突：不同材料描述不一致的内容，必须明确列出所有冲突来源和对应描述，禁止自行判断哪个正确，不做倾向选择
6. 严格遵循调研报告框架输出，不要增减模块，不要遗漏结构
【框架要求】
（使用 business-status-report skill 定义的标准框架）
【投喂材料】
（在此粘贴所有收集到的材料路径/内容）
```

### 你需要做的
- 检查AI生成的初稿结构是否正确，是否有明显的虚构内容（AI偶尔会编造合理但不存在的逻辑）

### 产出物
- 单领域调研报告初稿（末尾附待确认清单）

## 步骤2：精准信息校准（1-2天，含访谈）

### AI执行

1. **待确认清单按角色分类**，自动生成独立访谈提纲：
   - 产品经理：业务规则、设计意图、未来规划
   - 核心研发：代码实现、技术约束、隐性逻辑、历史遗留
   - 财务/运营等实际操作者：人工处理流程、审核标准、实际痛点、特批规则
   - 客服/一线：用户高频问题、驳回原因分布、工单投诉
   - 跨域对接人：跨域交互细节、异常处理、数据口径
   - 冲突类问题：明确列出冲突点和所有材料来源，标注需找哪几方核实

2. **每个问题自动补充上下文背景**（已有信息、冲突描述、代码/文档出处），避免访谈时反复追问基础问题

3. **访谈后自动处理**（投喂录音转写文字后）：
   - 区分「事实陈述」（可验证的规则/流程/数据）与「主观观点」（吐槽/个人判断/情绪），分别归类
   - 将确认的事实自动合并到报告对应章节，补全流程图/规则表/数据模型
   - 自动对比本次内容和已有文档/代码/前序访谈，标记所有冲突项
   - 识别文档/代码中未出现的特殊规则、灰色流程、口头约定，单独标记「待核实隐性规则」
   - 维护待确认清单状态（待访谈→已访谈待确认→已确认→冲突待验证），每轮更新进度

**访谈后处理固定Prompt**：
```
【最高优先级铁则】
1. 严格区分「事实陈述」和「主观观点」：
   - 事实陈述：可验证的规则、流程、数据、系统行为、已发生的事件，标注可信度
   - 主观观点：说话人的个人判断、情绪表达、对其他部门/人的评价、改进建议，不写入报告正文，单独列入「主观反馈」区
2. 冲突检测：逐条对比本次访谈内容和已有调研报告的对应章节，凡有不一致的地方，全部标记为「冲突项」，写明：冲突点、访谈中的说法、现有文档/代码中的说法、需要找谁进一步核实
3. 隐性规则捕获：凡提到文档和代码中没有出现过的特殊处理、口头约定、灰色流程、特批逻辑，单独标记为「待核实隐性规则」，不自行写入正文
4. 自动合并已确认的事实到报告对应章节，保持原报告结构不变
【投喂材料】
- 当前版本调研报告：（粘贴或传入文件路径）
- 访谈人角色：（产品/研发/财务/运营/客服/其他）
- 访谈录音转写文字：（粘贴转写内容）
```

### 你需要做的

1. **访谈前**：对照AI生成的提纲确认问题是否完整，补充你想了解的额外问题
2. **访谈中**：专注沟通和判断——
   - 判断说话人的可信度（他真的了解这个逻辑吗？在甩锅吗？）
   - 识别隐性博弈和政治约束（谁在推动/阻碍？哪些是领导拍板不能改的？）
   - 听言外之意（话没说透的真实原因）
3. **访谈后**：把录音转写投喂AI，审核AI提炼的信息是否准确，修正事实/观点误判
4. **补充AI拿不到的信息**：口头约定规则、离职员工留下的逻辑背景、未公开的业务规划

### 访谈顺序原则
- 不做全覆盖访谈，不一次问所有人
- 顺序：核心研发→产品经理→实际操作者→客服/一线
- 用前序访谈结论去验证下一个人，不要空对空
- 发现冲突不要回避，在下一轮直接抛出对质，往往能挖出深层原因

### 产出物
- 按角色分类的访谈提纲
- 每轮访谈后的纪要、冲突清单、报告增量更新
- 待确认清单核心项消项

## 步骤3：可视化内容自动生成（AI自动执行，0.5天）

### AI执行
基于校准后的信息，自动生成标准化可视化产出：
1. 核心流程泳道图（Mermaid格式）
2. 核心实体ER图（Mermaid格式）
3. 核心实体状态机图（Mermaid格式）——**按业务阶段线性排列，不画蜘蛛网**
4. 核心链路调用拓扑图
5. 所有表格（功能权限矩阵、规则清单、问题清单等）标准化排版

### 你需要做的
- 检查图中逻辑是否正确，调整业务视角说明，补充非研发能看懂的业务语义

### 产出物
- 可视化内容齐全的完整调研报告

## 步骤4：问题初判与历史溯源（1天）

### AI执行
1. 自动关联特殊逻辑/隐性规则的git提交时间、提交人、关联工单，匹配业务演进时间线，标记「疑似历史遗留设计」
2. 对比行业通用设计，标记差异较大的点、潜在性能/扩展性瓶颈
3. 基于线上工单/故障记录，关联每个已知问题的影响面、发生频率、关联代码量，初步评估风险等级

### 你需要做的
1. 验证AI标记的历史遗留是否准确，补充决策背景
2. 评估每个问题的实际业务影响，划分优先级，排除误判
3. 补充你的经验判断（如"这个逻辑每年大促都会出问题"）

### 产出物
- 报告「已知问题」模块补充完整，标注初步风险等级和历史背景

## 步骤5：文档定稿与知识库同步（0.5天）

### AI执行
1. 自动给文档中所有术语关联全局术语表链接，跨域节点关联对应领域文档链接
2. 自动生成知识库标签，按「领域-模块-问题类型」打标
3. 自动更新全局术语表，把本领域新增术语同步进去

**全局术语表更新Prompt**：
```
基于本次梳理的XX域报告，提取其中的通用术语，补充到全局术语表中，不要重复已有术语，不要修改已有术语的定义，有和已有术语冲突的列到冲突清单里待确认。
```

### 你需要做的
- 最终审核文档内容，补充个人经验沉淀的判断和说明
- 上传知识库，同步给相关对接人

### 产出物
- 定稿的单领域调研报告
- 更新后的全局术语表

## 跨域汇总阶段（所有核心领域梳理完后，2-3天）

1. AI自动提取所有单领域报告中的跨域依赖/流程/问题，生成全局架构总览初稿
2. AI自动识别跨域流程断点、数据不一致、职责重叠等全局问题
3. 你校准全局架构和问题，补充全局演进路线

## 避坑指南

1. **不要一开始就全量铺开**：先选简单域跑通流程，校准AI输出准确率和框架适用性
2. **不要相信没有来源的内容**：哪怕AI输出看起来再合理，没有明确来源标记就必须放到待确认清单
3. **不要提前做价值判断**：现状阶段只做事实记录，全量信息收集完再做诊断
4. **不要写跨域逻辑细节**：涉其他域只写交互点+文档链接，保持单领域内聚
5. **不要忽略隐性规则**：代码里哪怕一行硬编码、一个特殊判断，只要在生效就必须记录——80%线上故障来自不起眼的特殊逻辑
6. **不要把主观吐槽当事实**：抱怨/甩锅/个人评价单独归类，必须交叉验证后才写入正文
7. **不要回避冲突**：不同人说法不一致时记录下来，在下一轮对质，往往能挖出深层原因
8. **不要忘记标注"没有"**：系统没做什么（没有后端校验、没有最低金额检查）比做了什么同样重要
