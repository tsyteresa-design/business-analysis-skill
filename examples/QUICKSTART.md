# 快速上手指南：第一个业务域调研

本文档带你走完第一个业务域调研的完整流程，以「发票域」为例。

## 第一步：准备材料（0.5天）

按优先级收集以下材料，材料越全，AI初稿质量越高：

| 材料类型 | 优先级 | 示例 |
|----------|--------|------|
| 领域相关代码 | ⭐⭐⭐⭐⭐ | 发票服务代码、proto定义、定时任务代码 |
| 数据库表结构 | ⭐⭐⭐⭐⭐ | 建表SQL、model结构体定义 |
| 历史工单/故障记录 | ⭐⭐⭐⭐ | 近1年发票相关的JIRA工单、故障复盘 |
| 历史PRD/架构文档 | ⭐⭐⭐ | 发票域产品文档、架构设计文档 |
| 监控/性能数据 | ⭐⭐ | 开票成功率、耗时、驳回率等指标 |

> 💡 第一个域建议选边界清晰、历史债较少的领域跑通流程，不要一上来就啃最复杂的核心域。

## 第二步：启动流程生成初稿

在Claude Code中输入：
```
/business-domain-familiarization
```

然后按照提示，把所有材料路径或者内容粘贴进去，AI会自动生成调研报告初稿。

**初稿生成后检查要点**：
- [ ] 8个模块是否齐全
- [ ] 是否有明显虚构的逻辑（偶尔会有AI幻觉）
- [ ] 是否所有内容都有来源标注
- [ ] 缺口和冲突是否被正确标记

## 第三步：按角色做访谈校准

AI会自动根据待确认清单生成不同角色的访谈提纲，建议按以下顺序访谈：
1. **核心研发**（最了解代码真实逻辑）
2. **产品经理**（了解设计意图和未来规划）
3. **财务/运营**（了解实际操作流程和痛点）
4. **客服/一线**（了解用户侧问题和驳回原因）

> 💡 访谈技巧：用上一个人的结论去验证下一个人，发现冲突不要回避，直接抛出对质，往往能挖出深层原因。

每轮访谈后，把录音转写文字投喂给AI，AI会：
- 自动区分事实和主观观点
- 合并确认的信息到报告
- 标记新的冲突点和隐性规则
- 更新待确认清单

## 第四步：审核可视化内容

AI会自动生成：
- 按阶段分区的状态机图（不是蜘蛛网）
- 核心实体ER图
- 服务调用拓扑图
- 所有标准化表格

你需要做的是：
- 检查逻辑是否正确
- 补充业务语义，让非研发人员也能看懂
- 调整不符合业务视角的地方

## 第五步：问题溯源与定稿

AI会自动关联git提交历史和工单记录，标记历史遗留问题，你需要：
- 验证历史遗留的背景是否正确
- 评估问题的实际业务影响和优先级
- 补充你知道但代码/文档里没有的隐性规则
- 最终审核后定稿同步到知识库

## 常见问题

**Q: AI生成的内容有错误怎么办？**
A: 很正常，AI初稿大概有70-80%的准确率，你需要做的是校准而不是从零写。把错误的地方标记出来，投喂正确信息让AI修正即可。

**Q: 代码不全/没有文档可以做吗？**
A: 可以，只是缺口会多一些，AI会明确标记哪些地方是缺口，你可以针对性地通过访谈补全。

**Q: 一个域做完大概需要多久？**
A: 简单域3天左右，复杂核心域5天左右，比传统模式快3-4倍。

**Q: 可以用于其他类型的系统吗？**
A: 这套方法论主要针对中后台/交易类复杂业务系统，对于前端/C端系统可以适当调整模块框架。
